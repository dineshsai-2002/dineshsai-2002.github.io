What makes me different

A dashboard is only as good as the data behind it.

So I start with the data.

Data-quality first

Before building a chart I check for missing, incomplete and inconsistent records, then build tooling so the gaps get fixed at the source.

Built for non-technical teams

Branch-wise KPIs, student action lists and plain-language summaries, so the people who need the answer can act on it without asking an analyst.

Validate before reporting

Every dashboard number is reconciled against source data before it reaches senior stakeholders. Accuracy is the feature.

My approach

Understand

Turn the business question into a clear metric.

Clean & Validate

SQL checks for gaps, duplicates and inconsistencies.

Visualize

Dashboards and KPIs anyone can read at a glance.

Automate

Pipelines and scheduled reports that keep it fresh.

"I build reports that teams trust and act on, not one-off charts."
